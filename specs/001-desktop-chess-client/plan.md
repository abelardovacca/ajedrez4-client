## Summary

A desktop chess client (Windows, macOS, Linux) featuring:
- **Username entry** → **Lobby** (list of open games, create/join options) → **Game board** (full chess play with pixel-art aesthetics inspired by *Kathy Rain*)
- **Interaction model**: Click-to-move or drag-and-drop; board flipped for black player
- **Backend**: HTTP REST communication with ajedrez4-server (polling-based, 1–2 second intervals)
- **Visual style**: Hand-crafted pixel-art sprites, rich colour gradations, atmospheric UI
- **Scope**: No persistence; fresh session per launch; no authentication

**Structure Decision**: Single-project desktop GUI app with clean layering:
- **UI layer** (`src/ui/`): Screen rendering, widget logic, asset management
- **State layer** (`src/state/`): Application state machine, polling coordination, screen transitions
- **Adapter layer** (`src/adapter/`): HTTP client wrapping ajedrez4-server endpoints, error translation
- **Model layer** (`src/models/`): Data types consumed by UI and state logic
- **Assets**: Pixel-art sprites and colour palette created per specification

This structure preserves the Constitution's clean architecture principles: domain (chess rules) remains in server; client is purely view/state/adapter with no game logic.

## Phases

### Phase 0: Research (Output: research.md)

**Unknowns to resolve**:
1. **Language & framework**: Desktop app candidates (Rust/Egui? Python/PyQt5? C#/.NET? Electron/TypeScript?). Trade-off: build time, asset tooling, cross-platform story, pixel-art rendering capability.
2. **Asset pipeline**: How will pixel-art sprites be authored and exported? (Aseprite? Piskel? Hand-coded PNG slices?)
3. **HTTP client**: Async networking library choice (depends on language).
4. **Polling architecture**: Timer-based (spawn thread/task every 1–2s) vs event-driven (with backoff).
5. **Testing strategy**: Mocking the HTTP adapter for unit tests vs using test server.

**Research tasks**:
- Evaluate Rust (Egui) for fast, portable, low-resource footprint
- Evaluate Python (PyQt5) for rapid iteration and asset integration
- Evaluate Electron (TypeScript) for quick UI prototyping
- Find/recommend pixel-art asset tooling
- Document pros/cons, language decision recommendation
